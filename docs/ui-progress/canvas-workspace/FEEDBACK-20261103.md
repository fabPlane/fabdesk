# Feedback placement, visibility and lifetime · November 3, 2026

The user supplied a faint Artwork save message covering the canvas toolbar and requested a deliberate app-wide feedback policy. This follow-up implements a shared visual language and distinguishes confirmations from information a person must act on. It does not add an app-wide stream of notifications for every small interaction.

## UX decision and adoption

| Message | Placement | Lifetime / behavior |
| --- | --- | --- |
| Routine save confirmation with an independently visible saved state | Bottom-center of the task canvas, 96px above its bottom edge, clear of top tools and the corner assistant at the tested desktop size | 6 seconds of reading time; pauses on pointer hover, keyboard focus or a hidden document. Dismiss button; never takes focus when appearing. |
| Error / failed action | Inline in the relevant task or dialog | No timeout. Remains until a retry, correction or navigation replaces it. Artwork errors stay visible at the top of the scrolling tools pane. |
| Source/freshness warning or an actionable result | Inline near the affected outputs / controls | No timeout. Keep Review, Retry, Download and other next-step controls accessible. Dismiss where appropriate; dismissal does not mark a design checked. |
| Progress | Beside the running action; existing background preview activity uses the bottom-center canvas position | Remains while running. No invented completion or cancellation. Hiding background activity does not cancel its task. |
| Copy confirmation | On the copy control itself | Brief success indicator. Chat copy failures now persist until another attempt instead of disappearing after 2.5 seconds. |

The exact six-second duration and bottom-center position are product choices, not claims that a standard prescribes them. Temporary confirmations are redundant with the saved state still in the task. Live announcement roles do not move focus ([W3C status messages](https://www.w3.org/WAI/WCAG21/Understanding/status-messages)); consequential messages and actions have no reading deadline ([W3C timing guidance](https://www.w3.org/WAI/WCAG22/Understanding/timing-adjustable)). This is not an accessibility-conformance certification.

Shared cards use an opaque theme panel, readable foreground copy, a clear title, severity icon, colored leading border, consistent padding and a bounded dismiss target. Floating confirmations add a stronger shadow; inline cards do not float over the canvas. Reduced-motion and forced-color styles are included.

Adopted in Artwork, live assembly-preview activity, Outputs library generation/errors/review filters, Review output updates, export completion panels, Shopping list updates/errors and Voice setup results. Shared ErrorNotice cards retain their recovery actions and collapsed technical details with the same visual treatment. Existing field validation, source receipts, engineering warnings and button-local copy indicators keep their context. Enclosure, placement and resize behavior is unchanged.

Not tested: every downstream task state, real export failure/success, supplier/cloud mutations, Voice setup/credentials, live assembly-preview changes, clipboard rejection, hidden-document pause, alternate themes, small-window collisions, forced colors or screen-reader speech. Native checks used the current full-size desktop window. Bottom-center notices can briefly cover lower preview content; they avoid toolbar and assistant controls at the tested size and can be dismissed. No global error queue, new notification history or duplicate status stream was introduced.
