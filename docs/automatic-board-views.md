# Automatic board views

The Board workspace offers 2D, 3D and Layers. 2D and 3D share the same orthographic camera and saved PCB model. Switching to 3D preserves the current top/bottom view, pan and zoom; drag to tilt it. Top/Bottom buttons work in both modes, including clicking the current side again to reset a rotated view. Returning to 2D flattens the selected side. Visiting Layers leaves the hidden model camera unchanged. Pan, zoom, component selection and Fit remain available. Layers displays KiCad's actual enabled copper stack, paste, mask, silkscreen and outline with independent visibility controls.

Opening a saved board prepares missing/outdated model and layer previews in the background. Preparation is keyed by endpoint, project, source/manifest identity and PCB SHA-256. View switching reuses the canvas and decoded model. Source edits settle before preparation; errors require an explicit retry rather than an export loop. An installed compatible KiCad version can be used without changing user settings. No source board is rewritten.

The existing schematic, routing, placement and checks remain available. The source drawing and pinned comments are under **More board tools → PCB drawing & comments**. Existing saved finding/comment navigation opens that drawing directly. Component-model export notes remain visible; these previews do not establish manufacturing or physical fit.

## Validation

- Root typecheck and desktop production build passed.
- UI: 409 tests passed. Client core: 616 tests passed.
- Focused registry/preview tests: 77 passed. GLB integrity and preview publication tests: 14 passed.
- New tests cover actual layer enumeration, immutable source export, preservation of previous output after an edit, revision matching, failed queued jobs and layer visibility.
- Live desktop: a real four-layer VAIO peripheral board and two-layer microSD board, both as separate assembly sources with no pre-existing previews. Automatic preparation produced 11 and 9 layer images respectively; both bundles matched their source SHA-256 and models were independently saved (6.9 MB and 1.2 MB).
- Six successive view switches retained the same WebGL canvas. Two-frame observations took 7–31 ms on the tested machine, after initial preparation. Top/Bottom and layer toggles passed. This is an interaction smoke check, not a cross-device performance guarantee.
- Camera correction: pixel comparisons of the rendered board viewport matched exactly between 2D and 3D for both top and bottom, including pan/zoom (excluding the interaction-hint text). Native mouse-drag rotation and keyboard orbit were verified in 3D. Four regression tests cover camera preservation and returning from an orbit to 2D.
- Lighting: neutral tone mapping, a locally generated studio reflection map, and camera-relative key/fill lights reveal metallic contacts on both sides without adding a continuous render loop. Known native KiCad silkscreen uses opaque depth-tested ink so transparent soldermask cannot fade individual letters when rotating. Component/enclosure glass and textured alpha artwork remain unchanged. Two material regression tests and live top/bottom/oblique checks passed; 2D/3D matching was rechecked. Overlapping source artwork and unavailable component models are not repaired by lighting.
- Performance: static opaque primitives are batched only inside their original component, retaining picking, highlighting, materials and every triangle. Transparent, animated, mirrored, partial-range and individually identified meshes stay separate. Input/resize/focus redraws coalesce to one animation frame; idle views do not continuously render.
- Real asset counts: VAIO peripheral 9,961 → 159 meshes, unchanged 117,198 triangles; microSD 1,778 → 42 meshes, unchanged 18,310 triangles. The peripheral's top-view board image was pixel-identical before/after batching. Live U1 selection, 3D Top/Bottom and repeated Top reset passed.
- Same-computer peripheral orbit benchmark (90 animation-frame keyboard steps through OrbitControls, 1440×920 app): median frame interval 55.6 → 5.6 ms, p95 61.3 → 5.6 ms. This includes removing duplicate draws; results depend on hardware, display refresh rate and board complexity, and are not a JLCPCB benchmark or a universal frame-rate guarantee.
- 2D pan follow-up: OrbitControls suppresses change events below its world-space movement threshold. An actual 8-pixel mouse drag on the microSD board previously produced no changed board pixels; after invalidating active pointer moves it produces the exact 8-pixel translation. Input invalidation still coalesces with normal change events into one render per frame. Hover stays idle and handlers are removed on teardown. Regression coverage uses real OrbitControls at PCB scale, plus mouse/touch/wheel and cleanup cases.
- Broader Windows tools/KiCad suites are not fully green. Their existing failures were reproduced in a separate checkout of `main` (`b7bc58cb`), including symlink privileges, shell-based CLI fixtures, stencil and other platform-sensitive checks. The two changed inventory assertions (tab/tool additions) were updated and passed on rerun.

Screenshots in `screenshots/automatic-board-views/` show the actual app using the VAIO peripheral source, not mockups.

Toolbar spacing: Top/Bottom and part selection now share one compact row. Main actions have consistent 36px targets; secondary board tools use a named overflow menu. Selection warnings and focus/clear remain available. The live desktop was checked at 1636x920, 1024x920 and maximized: no clipped controls at the tested sizes, selection highlighted U1, Focus/Clear worked, and Top/Bottom plus 2D/3D/Layers remained usable. The wide toolbar reserves 48px less height than before. UI typecheck, all 409 UI tests and desktop build passed after the change.
